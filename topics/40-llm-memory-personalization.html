LLM Memory & Personalization

Giving a stateless model a usable past — deciding what to remember about a user, where to store it, when to forget it, and how to let them delete it.

Foundation

What Is It?

A transformer is, by construction, stateless between calls. Everything it appears to know about you exists either in its frozen weights or in the tokens you just sent it. The moment a conversation ends, that context is gone. Memory research asks how to build a persistent, evolving representation of a user and their history on top of an architecture that has no native notion of yesterday — and personalization asks what to do with it once you have it.

It helps to be precise about where knowledge can live, because the three locations have completely different cost, latency, and governance properties. In-context memory is text in the prompt: instantly writable, perfectly inspectable, and bounded by the window and by attention cost. Parametric memory lives in the weights: free at inference time and deeply integrated with the model's other knowledge, but expensive to write, opaque, and difficult to selectively remove. External memory is a store — vector index, key-value database, or document set — queried at request time: cheap, unbounded, auditable, and deletable, but only as good as the retrieval step that decides what to surface.

Simple Analogy

Consider a good family doctor. Working memory is what you have told them in the last five minutes. Their case notes are an external store — searchable, correctable, and something you have the right to read and amend. And then there is what has become second nature after twenty years of practice, which no longer feels like recall at all; that is the parametric layer, powerful but nearly impossible to edit on request. A useful assistant needs all three, and most current failures come from putting information in the wrong one.

The naive strategy of appending the entire history to every prompt fails on all three axes: attention cost grows with sequence length, models attend unevenly to very long inputs, and irrelevant history actively distracts. So real systems build hierarchies. MemGPT (Packer et al., 2023) framed this explicitly as virtual context management, treating the window as RAM and an external store as disk, with the model itself issuing function calls to page information in and out. Generative Agents (Park et al., 2023) contributed the other influential design: a memory stream of timestamped natural-language observations, retrieved by a score combining recency, importance, and relevance, with periodic reflection steps that synthesise higher-level inferences from accumulated low-level records. Nearly every production memory feature is a descendant of one of these two designs.

Motivation

Why It Matters

Memory is what separates a useful tool you re-brief every morning from a collaborator that accumulates context about your work — and it is simultaneously the feature with the sharpest privacy consequences.

  • 🧵 Continuity across sessions: Long-running work — a research project, a codebase, a course of treatment — depends on retaining decisions and constraints from weeks ago. Without memory, the user pays a re-briefing tax on every interaction.
  • 🎯 Fewer tokens, better answers: A compact profile of stable preferences usually beats stuffing the whole transcript into the window, both on cost and on quality, because irrelevant history measurably degrades reasoning.
  • 🧑‍🔬 Agents need state: Any agent that works over hours or days must record what it tried, what failed, and what it learned. Memory is the substrate for experience-based improvement without retraining.
  • 🔐 Privacy becomes a design problem: Once a system writes durably about people, questions of consent, retention, inspection, and deletion move from policy documents into the architecture. Data placed in weights is far harder to honour a deletion request for than data in a row of a database.
  • ⚖️ Personalization pulls against alignment: A model that adapts to a user's views can slide into flattery and reinforcement of what they already believe. Deciding which preferences to accommodate and which to hold constant is a value judgement embedded in a retrieval policy.
Mechanism

How It Works

A memory system is a loop with four decisions: what to write, how to organise and compress it, what to retrieve for the current turn, and how to reconcile retrieved memories with what the model already believes. The retrieval half is comparatively well understood — it borrows directly from retrieval-augmented generation — while the write and reconcile halves are where the open research is.

Write policies: The hardest question is what deserves to be remembered at all. Recording everything produces a store full of chatter that swamps retrieval; recording too little defeats the purpose. Practical approaches include letting the model itself call an explicit write tool when it judges something durable, running a lightweight classifier over each turn for candidate facts and preferences, and extracting structured slots after a session ends. The good signals are things that are stable and reusable — a dietary restriction, a preferred programming language, a project deadline — as opposed to transient state. Extraction is also where errors are silently injected: a preference misread once and written confidently will be retrieved for months, so writes need provenance, timestamps, and ideally a confidence level.

Consolidation and forgetting: Because memory grows monotonically, every system needs a compaction strategy. Recursive summarisation collapses old episodes into shorter abstracts; reflection synthesises specific observations into general statements such as an inferred interest; deduplication merges near-identical entries; and supersession replaces stale facts when a newer one contradicts them, which requires knowing the difference between an update and a genuine conflict. Forgetting deserves to be treated as a first-class feature rather than an accident of eviction: time-to-live on facts that are inherently temporary, decay on entries never retrieved, and hard deletion on request. The parametric route works differently — targeted editing methods like ROME (Meng et al., 2022) locate a factual association in the mid-layer feed-forward weights and apply a rank-one update, and MEMIT extends this to thousands of edits at once. Both are elegant, and both are brittle: edits often fail to propagate to logically entailed facts, can be undone by paraphrasing the query, and degrade nearby unrelated knowledge as their number grows, which is why most deployed personalization stays out of the weights.

Reconciliation at inference: When a memory is retrieved it enters a prompt that also contains fresh documents, the user's current message, and a system policy — and these sources disagree more often than one might expect. Studies of knowledge conflict find models can be stubbornly attached to a well-learned parametric fact even when the context contradicts it, and conversely can be over-credulous towards retrieved text that is wrong. Handling this well means encoding an explicit precedence — a user's stated correction should beat a stored memory, which should beat a parametric prior — and surfacing it to the user when the system acts on something remembered rather than something said. Interfaces that show which memory was used, and let the user edit or delete it in place, turn an opaque behaviour into a correctable one.

Techniques

Key Techniques

Virtual Context Management

Treat the window as a paged working set over a larger external store, with the model issuing its own read and write calls. Gives unbounded effective memory, but every page-in costs a model call and the policy is only as good as the model's judgement.

Memory Streams with Reflection

Store timestamped natural-language observations, retrieve by recency, importance, and relevance, and periodically synthesise higher-level inferences. Produces coherent long-horizon behaviour; the scoring weights are largely hand-tuned heuristics.

Structured User Profiles

Maintain a compact typed record of stable attributes and preferences that is always injected. Cheap, inspectable, and easy to expose in a settings interface, but rigid — anything not anticipated by the schema has nowhere to live.

Recursive Summarisation

Compress older history into progressively shorter abstracts to keep the store bounded. Controls growth well, at the cost of irreversible detail loss and drift, since each summarisation pass can amplify an earlier misreading.

Targeted Weight Editing

Locate and rewrite a specific factual association directly in the parameters, as in ROME and its batched successor MEMIT. Zero inference overhead, but brittle under paraphrase, poor at propagating implications, and hard to audit or undo.

Per-User Adapters

Train a small low-rank adapter per user or cohort so preferences live in dedicated parameters. Captures hard-to-verbalise style, but adds training and serving complexity and makes deletion a retraining problem rather than a row delete.

Challenges

Challenges

🥊

Knowledge Conflicts

Stored memory, retrieved documents, and parametric priors routinely disagree, and models lack a principled precedence order. The result is answers that are confidently wrong in a way the user cannot trace to a source.

🕰️

Staleness & Forgetting

Facts about people expire — jobs, cities, goals, relationships. Distinguishing an update from a contradiction, and deciding what should decay on its own, is unsolved, so old memories resurface long after they stopped being true.

🔒

Privacy & Deletion

Some things must never be persisted, and users need real inspection and erasure. Text stores can honour that; weights and derived summaries cannot easily, and memorisation of training data shows how leaky parameters already are.

📏

Evaluation Is Very Hard

Testing memory requires long, realistic, multi-session interactions with ground truth about what should have been retained. Synthetic probes are easy to game, and human studies at that horizon are slow and expensive to run.

Literature

Key Papers & Resources

  • 📄
    MemGPT: Towards LLMs as Operating Systems
    Packer et al., 2023 — Introduces virtual context management, letting a model page information between a limited window and external storage via its own function calls.
  • 📄
    Generative Agents: Interactive Simulacra of Human Behavior
    Park et al., 2023 — Proposes the memory stream with recency, importance, and relevance retrieval plus reflection and planning, the template for most agent memory designs.
  • 📄
    Locating and Editing Factual Associations in GPT (ROME)
    Meng et al., 2022 — Traces factual recall to mid-layer feed-forward modules and edits a single association with a rank-one weight update.
  • 📄
    Mass-Editing Memory in a Transformer (MEMIT)
    Meng et al., 2023 — Scales direct weight editing to thousands of simultaneous factual updates, and exposes how accuracy and locality degrade as edit counts rise.
  • 📄
    Extracting Training Data from Large Language Models
    Carlini et al., 2021 — Demonstrates verbatim recovery of memorised sequences including personal information, framing why durable storage of user data needs care.
Looking Ahead

Future Directions

  • Learned write and forget policies: Replacing hand-tuned heuristics with policies trained end-to-end against downstream task success, so the system learns what is worth remembering and when a memory has stopped earning its place.
  • Architectures with native state: Recurrent and state-space hybrids, or trainable memory modules updated online, that give a model persistent state without either an ever-growing prompt or a fragile weight edit.
  • Privacy-preserving personalization: Keeping the user's memory on their own device or under their own key, combining local adapters with federated updates so a provider can improve the shared model without ever holding the personal store.
  • Longitudinal benchmarks: Multi-session evaluation suites with explicit ground truth for retention, correct updating, principled forgetting, and honouring deletion — measuring memory as a capability rather than as a side effect of a long context window.
